# ContainerBar Backlog

Prioritized list of planned features, improvements, and technical debt for ContainerBar - macOS menu bar Docker/Podman monitoring app.

Item ids are stable `CB-NNN` numbers and are never reused. Completed items move to [`docs/resolved.md`](resolved.md).

## Low Priority

### CB-058: Automate the console-side smoke launch on the Mac mini
**Priority**: Low
**Description**: Filed during CB-048. `scripts/smoke-launch-mini.sh` verifies the distributed zip's codesign/Gatekeeper/staple over SSH, but the actual menu-bar app launch cannot be automated over a plain SSH connection (no window server; GUI automation over SSH is a standing no-go on the mini). Today the helper only launches when a GUI session happens to be present and otherwise prints a manual `open -a` command to run from the mini's console. Follow-up: wire the real launch into a console session on the mini — e.g. drive it through the existing Prowl QA runner (which already holds an Accessibility grant and a console/launchd context) against the notarized artifact, so the clean-machine smoke launch is fully automated at release time rather than a documented manual step. Coordinates with the CB-042 Prowl QA setup.

### CB-061: Dashboard view-body coverage with ViewInspector
**Priority**: Low
**Description**: Follow-up to CB-060, which added ViewInspector (test-only, pinned 0.10.3, `ContainerBarTests` target only) and covered the Settings panes. Extend view-body coverage to the Dashboard layer under `Sources/ContainerBar/Views/Dashboard/`, which is still at ~0% line coverage. **Start with the parameter-injected views — ViewInspector can inspect these today** because they receive their data through `let` init parameters rather than `@Environment`: `ContainerCardView` (`container`, `stats`, `onAction` — assert the name/image/status render, the CPU/memory labels reflect the injected `ContainerStats`, and the action buttons carry their identifiers), `ContainerGroupView` (`group`, `stats` — one card per container, running-first ordering, running/total counts), `QuickActionBar` (the refresh/hosts/logs/settings buttons render and are wired to their closures), plus `MetricGaugeView`, `MetricSparklineCard`, and `DashboardHeaderView` (assert gauge/spark values and header text derive from the injected model). Follow the CB-060 test patterns: `@MainActor` suites, `import Testing`, fixtures via `MockDockerAPIClient`/fixture models, one file per view under ~300 lines, and locate elements by the CB-052 accessibility identifiers (add an `accessibilityIdentifier` only if an element genuinely lacks one). **Known constraint carried from CB-060:** ViewInspector 0.10.3 on this toolchain cannot inspect a body that reads an Observation-framework `@Environment(Type.self)`, so `DashboardMenuView` and `HostPanelView` (both read `@Environment(ContainerStore.self)`/`@Environment(SettingsStore.self)`) are **not** coverable without either upstream ViewInspector support or a disallowed source-level inspection hook — document them as blocked (as CB-060 did for the three env-reading Settings panes) rather than contorting the views. Pair with CB-052 (accessibility) since both touch the view layer.
